Build a RISC-V CPU: Your Course Flow

A self-paced curriculum from digital logic fundamentals through a taped-out (well, simulated tape-out) RISC-V core — with a physical design capstone, since that's where you're headed professionally. Budget roughly 4–6 months at a steady pace, less if you already have strong RTL chops.

Phase 0 — Prerequisites Check (1 week)

Before touching RTL, make sure these are solid:

  • Digital logic: combinational vs. sequential logic, FSMs, timing (setup/hold), pipelining basics
  • Computer architecture: instruction sets, datapath vs. control, memory hierarchy basics
  • A hardware description language: Verilog or SystemVerilog syntax (you don't need to be fluent yet, just literate)

Free resources:

  • Nand2Tetris (nand2tetris.org) — builds a CPU from NAND gates up; great if logic design feels shaky
  • Harris & Harris, Digital Design and Computer Architecture, RISC-V Edition — the textbook most RISC-V courses use; check UT Austin's library for a legal digital copy
  • UC Berkeley CS61C / CS152 lecture notes (free online) — architecture fundamentals

Milestone: You can read a Verilog always block and explain what hardware it describes.

Phase 1 — Learn the RISC-V ISA (1–2 weeks)

You need to know the instruction set cold before you implement it.

  • Read the RISC-V Unprivileged ISA Specification (free PDF, riscv.org) — focus on RV32I (the base 32-bit integer instruction set). Skip privileged/extension chapters for now.
  • Understand the instruction formats (R, I, S, B, U, J-type), the register file (x0–x31), and how immediates are encoded.

Free tools to play with instructions before building hardware:

  • Ripes (github.com/mortbopet/Ripes) — a free, open-source RISC-V pipeline simulator with visual datapath diagrams. Write assembly, watch it execute cycle-by-cycle through single-cycle, 5-stage, or superscalar pipelines. This is the single best "see it before you build it" tool available.
  • Venus (venus.cs61c.org) — browser-based RISC-V simulator, zero install
  • RISC-V GNU Toolchain (github.com/riscv-collab/riscv-gnu-toolchain) — free cross-compiler so you can compile C to RISC-V assembly and study the output

Milestone: Hand-assemble a short RV32I program (10–15 instructions) into machine code without tool assistance.

Phase 2 — Single-Cycle CPU in RTL (2–3 weeks)

Build the simplest possible working core: one instruction fully executes per clock cycle.

Scope: RV32I, no pipelining, no hazards, no memory-mapped I/O yet. Datapath: PC, instruction memory, register file, ALU, data memory, control unit.

Free tools:

  • Icarus Verilog (iverilog) — free, open-source Verilog simulator/compiler. Install via apt install iverilog or from GitHub. This is your day-to-day compile-and-run tool.
  • GTKWave — free waveform viewer, pairs with Icarus Verilog. You'll live in this tool debugging timing and control signals.
  • Visual Studio Code + a Verilog/SystemVerilog extension (free) for syntax highlighting and linting

Workflow: write module → iverilog compile → run testbench → dump .vcd → inspect in GTKWave → fix → repeat.

Milestone: Your core correctly executes a hand-written program exercising every RV32I instruction category (arithmetic, loads/stores, branches, jumps).

Phase 3 — Verification Discipline (1–2 weeks, but ongoing forever)

Before you pipeline anything, learn to verify properly — this habit pays off for the rest of the project (and your career).

  • Write directed testbenches for each instruction
  • Move to self-checking testbenches (compare against expected register/memory state automatically, not by eyeballing waveforms)
  • Learn RISC-V's official compliance/architecture test suite: riscv-software-src/riscv-tests and riscv-arch-test (both free on GitHub) — run these against your core for real ISA compliance signal

Free tools:

  • Verilator (veripool.org) — free, extremely fast Verilog/SystemVerilog simulator that compiles your design to C++. Industry-standard for open-source RTL verification; learning it now pays off later.
  • cocotb (free, Python-based testbench framework) — lets you write testbenches in Python instead of Verilog, much faster to iterate

Milestone: Your single-cycle core passes the official rv32ui (RV32 user integer) test suite.

Phase 4 — Pipelined CPU (3–5 weeks)

Convert your single-cycle design into a classic 5-stage pipeline (IF/ID/EX/MEM/WB) — this is where computer architecture really starts.

  • Add pipeline registers between stages
  • Implement hazard detection: data hazards (RAW), and resolve with forwarding/bypassing and stalling where forwarding can't help (e.g., load-use hazard)
  • Implement control hazard handling: branch/jump misprediction, flushing

Free tools:

  • Keep using Verilator + cocotb — pipelines make bugs subtle, and a fast, scriptable simulator matters a lot here
  • Ripes again, side-by-side — it visualizes exactly this kind of hazard/forwarding logic, useful as a reference model when your own pipeline misbehaves

Milestone: Passes the full rv32ui suite with the pipeline active, and correctly handles a hand-crafted hazard-stress-test program (back-to-back dependent instructions, branches immediately followed by dependent instructions, etc).

Phase 5 — Memory System & Peripherals (2–3 weeks)

Turn your core into something that can actually run a program from memory and talk to the outside world.

  • Instruction/data memory as separate or unified (Harvard vs. von Neumann) BRAM-style models
  • Simple memory-mapped I/O (e.g., a UART for printf-style debug output)
  • Optional: a minimal AXI-Lite or Wishbone bus interface — teaches you the bus protocols real SoCs use

Free references:

  • PicoRV32 (github.com/YosysHQ/picorv32) — a small, well-documented, open-source RV32I core. Read its source once you have your own working; comparing designs teaches a lot.
  • SERV (github.com/olofk/serv) — the world's smallest RISC-V core (bit-serial); interesting for a completely different design philosophy
  • VexRiscv / Ibex (lowRISC) — more sophisticated free cores if you want to see production-quality style later

Milestone: Your core runs a compiled C "Hello World" that prints over a simulated UART.

Phase 6 — FPGA Bring-Up (2–3 weeks)

Get your design running on real silicon (an FPGA) instead of just simulation — a big motivational milestone.

Free/open toolchain (if you have or can access a Lattice iCE40 or ECP5 board):

  • Yosys — free, open-source synthesis tool (Verilog → gate-level netlist)
  • nextpnr — free place-and-route tool
  • Project IceStorm / Project Trellis — free bitstream tools for Lattice iCE40/ECP5 FPGAs
  • Together these form a fully open-source FPGA toolchain (no vendor license needed)

If you have access to Xilinx/Intel hardware instead (e.g., through UT Austin's ECE labs):

  • Xilinx Vivado (free WebPACK edition) or Intel Quartus Prime Lite (free edition) — proprietary but no-cost for smaller devices

Milestone: Your core runs on physical FPGA hardware, with UART output visible on a serial terminal on your laptop.

Phase 7 — Physical Design Capstone: RTL to GDSII (3–4 weeks)

This is the part that connects straight to your interest in ASIC physical design — take your verified RTL all the way to a manufacturable layout using a fully open-source flow.

Free tools (the open-source ASIC flow):

  • Yosys — RTL synthesis (same tool as Phase 6)
  • OpenROAD — free, open-source place-and-route, floorplanning, clock tree synthesis (CTS), and static timing analysis engine
  • OpenLane / OpenLane 2 — the automated flow that chains Yosys → OpenROAD → Magic → Netgen → KLayout into a single RTL-to-GDSII pipeline
  • SkyWater SKY130 PDK — free, open-source 130nm process design kit (the thing that makes all of this legally and technically possible without a foundry NDA)
  • Magic VLSI — free layout tool, used for DRC (design rule checking) and extraction
  • Netgen — free LVS (layout-vs-schematic) verification
  • KLayout — free GDSII viewer/editor, good for visually inspecting your final layout
  • OpenSTA — free static timing analysis (bundled with OpenROAD)

How to start without a painful local install: Google/ChipsAlliance publish a free Colab notebook that runs OpenLane in the browser with zero setup — good for your first end-to-end run before committing to a local Docker install.

Suggested capstone target: Don't try to push your full pipelined core through first. Start by hardening PicoRV32 (a known-good, well-tested small core) through the full flow so you learn OpenLane's floorplan/placement/CTS/routing knobs without debugging your own RTL bugs at the same time. Then run your own core through it as the "real" capstone.

Milestone: A clean GDSII layout of your core with zero DRC violations, passing LVS, and timing closure at a target clock frequency — viewable in KLayout.

Ongoing: Reference Cores Worth Reading

Alongside your own build, periodically read the source of these free, open-source cores — seeing multiple design philosophies accelerates learning a lot:

Core Why read it
PicoRV32 Small, clean, heavily used as a teaching/reference design
SERV Radically minimal (bit-serial) — teaches what's actually essential
Ibex (lowRISC) Production-quality style, used in real silicon (OpenTitan)
VexRiscv Written in SpinalHDL — good exposure to HDL generators beyond Verilog
Rocket Chip Full out-of-order-capable, Chisel-based — aspirational reading once you're comfortable

Suggested Pace Summary

Phase Focus Est. time
0 Prerequisites 1 week
1 ISA literacy 1–2 weeks
2 Single-cycle core 2–3 weeks
3 Verification discipline 1–2 weeks (ongoing)
4 Pipelining 3–5 weeks
5 Memory & I/O 2–3 weeks
6 FPGA bring-up 2–3 weeks
7 Physical design (RTL→GDSII) 3–4 weeks

Total: roughly 15–23 weeks at a consistent few-hours-a-week pace, faster if you can dedicate more time (e.g., over a summer).
